# [ADR-0000] El patrón Strangler Fig 

Se decidió aplicar el patrón Strangler Fig para modernizar el sistema legado de forma gradual. Cada módulo será reemplazado progresivamente por nuevos servicios, manteniendo operativas las funcionalidades que aún dependan del sistema anterior. Esta estrategia reduce los riesgos de la migración, facilita la validación de cada componente y garantiza la continuidad del servicio durante todo el proceso.

## 1. Contexto y Declaración del Problema

El patrón Strangler Fig suele ser una alternativa más segura que un Big Bang Rewrite, ya que permite sustituir un sistema legado de forma gradual, sin tener que esperar a que la nueva solución esté completamente terminada.

Caso práctico: imaginemos una tienda en línea cuyo sistema legado gestiona usuarios, productos, pedidos y pagos. En lugar de reemplazar toda la plataforma de una sola vez, se puede comenzar migrando únicamente el módulo de productos. Un proxy o capa de enrutamiento dirige las consultas de productos al nuevo servicio, mientras que las demás solicitudes continúan siendo atendidas por el sistema legado. Después se migran progresivamente los módulos de usuarios, pedidos y pagos, hasta retirar por completo la aplicación anterior.

Este enfoque permite:

Mantener el servicio disponible durante la migración.
Reducir el riesgo al realizar cambios pequeños y controlados.
Comprobar cada módulo en producción antes de continuar.
Revertir rápidamente una migración si aparece algún problema.
Entregar mejoras a los usuarios sin esperar a completar toda la nueva plataforma.
A diferencia de un Big Bang Rewrite, donde todo el sistema se sustituye en una única puesta en producción, el patrón Strangler Fig facilita una transición progresiva y reduce tanto el impacto operativo como la posibilidad de una interrupción general del servicio.
