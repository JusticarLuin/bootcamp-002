# Modelado de Amenazas STRIDE - Módulo Products

1. **Objetivo**

El presente documento describe el modelado de amenazas de seguridad del módulo Products, utilizando la metodología STRIDE, como parte del proceso de migración del sistema legado.

El análisis se realiza sobre los elementos identificados en el Diagrama de Flujo de Datos (DFD), considerando entidades externas, procesos, flujos de datos, almacenes de datos y límites de confianza

---

2. **Alcance**

El análisis considera el siguiente endpoint:

Elemento	Descripción
Módulo	Products
Método	GET
Endpoint	/api/v1/products/{id}
Acceso	Público
Descripción	Obtiene el detalle de un producto
Entrada	Path parameter id
Tipo de identificador	UUID o Integer, sujeto a definición del contrato
Body de entrada	No aplica
Salida	Información pública del producto

3. **Arquitectura y flujo analizado**

Arquitectura y flujo analizado
El flujo de la petición es el siguiente:

Cliente → Kong API Gateway → Microservicio Products → Base de Datos

Se identifican los siguientes elementos dentro del DFD:

Elemento	Tipo DFD	STRIDE aplicable
Cliente	Entidad externa	S, R
Cliente → Kong	Flujo de datos	T, I, D
Kong API Gateway	Proceso	S, T, R, I, D, E
Kong → Products	Flujo de datos	T, I, D
Microservicio Products	Proceso	S, T, R, I, D, E
Products → DB	Flujo de datos	T, I, D
Base de Datos	Almacén de datos	T, R, I, D
Límites de confianza identificados
Internet → API Gateway.
API Gateway → Red interna.
Microservicio Products → Base de Datos.
Todo dato que cruza un límite de confianza debe considerarse no confiable hasta ser validado por el componente receptor.

---

4. **Análisis STRIDE**

Elemento STRIDE	Riesgo identificado	Mitigación
Cliente	S, R	Suplantación de origen y falta de trazabilidad	Validación de headers, HTTPS y logs
Cliente → Kong	T, I, D	Manipulación del id, exposición de datos y solicitudes excesivas	TLS, validación y Rate Limiting
Kong API Gateway	S, T, R, I, D, E	Manipulación, exposición, pérdida de trazabilidad y saturación	TLS, Rate Limiting, logs y mínimo privilegio
Kong → Products	T, I, D	Alteración o exposición del tráfico y exceso de solicitudes	TLS, restricciones de red y timeouts
Products	S, T, R, I, D, E	Manipulación del id, exposición de información, saturación y privilegios excesivos	Validación, consultas parametrizadas, DTO público, logs y mínimo privilegio
Products → DB	T, I, D	Manipulación de consultas, exposición y agotamiento de conexiones	Consultas parametrizadas, TLS, pool y timeouts
Base de Datos	T, R, I, D	Alteración, falta de auditoría, exposición y saturación	Solo lectura, auditoría, índices y monitoreo
Riesgo residual
Después de aplicar los controles definidos, el riesgo residual se considera principalmente Medio. Los controles deberán validarse en el ambiente antes de considerar las amenazas como mitigadas.

5. **Riesgo residual y conclusión**
El endpoint /api/v1/products/{id} ha sido definido como un servicio público, por lo que la ausencia de autenticación no se considera por sí misma una vulnerabilidad.

Los principales riesgos identificados están relacionados con:

Manipulación del parámetro {id}.
Divulgación de información interna.
Enumeración de productos.
Denegación de servicio por consumo masivo.
Falta de trazabilidad de consumidores anónimos.
Privilegios excesivos del microservicio o usuario de Base de Datos.
Acceso directo al backend evitando Kong.
La implementación de validación estricta de entradas, HTTPS/TLS, Rate Limiting, consultas parametrizadas, DTOs públicos, logging centralizado, mínimo privilegio, restricciones de red y mecanismos de resiliencia permite reducir los riesgos identificados.

El riesgo residual deberá ser revisado después de validar técnicamente que los controles definidos se encuentran implementados en el ambiente correspondiente.
